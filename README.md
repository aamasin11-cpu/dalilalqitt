## 3. طريقة العمل

```bash
cd /workspace/output/build

# 1) بناء الموقع (يقرأ المحتوى ويولّد site/)
python3 build.py

# 2) توليد صورة OG وأيقونة التطبيق
python3 make_images.py

# 3) فحص بصري (سطح مكتب + جوال) وحفظ اللقطات في ../preview
python3 shots.py

# 4) فحص سلامة النصوص العربية (يجب أن يطبع 0 ملاحظات)
python3 lint_text.py content/bodies/cat-feeding-by-age.html

# 5) فحص ملفات XML (sitemap.xml و blogfeed) — يطبع TOTAL ISSUES: 0
python3 fix_xml.py ../site --all

# 6) تدقيق عميق: توازن الوسوم، تكرار Meta/Schema/Canonical، الروابط، الترميز
python3 audit_site.py
```

### نتيجة التدقيق الكاملة (آخر تشغيل)

```
صفحات HTML مفحوصة: 29 | ملفات XML: 4
روابط داخلية: 1450 (كلها تعمل) | روابط خارجية: 218 (كلها https)
لا توجد مشاكل — كل الملفات سليمة تماماً.
TOTAL ISSUES: 0
```

> بعد أي تعديل على `content/` نفّذ `build.py` ثم `make_images.py`.

## 4. كيف تضيف مقالاً جديداً

1. **اكتب الجسم** في `content/bodies/<slug>.html` (HTML فقط، دون `<html>`).
  _وفق البنية الموضحة في `ARTICLE_SPEC.md`_.

2. **أنشئ البيانات الوصفية** في `content/meta/<slug>.json`:

```json
{
  "slug": "my-new-article",
  "title": "عنوان المقال",
  "meta_description": "وصف بين 140 و160 حرفاً",
  "category": "health",
  "date": "2026-11-23",
  "updated": "2026-11-23",
  "reading_minutes": 8,
  "excerpt": "جملة تلخّص المقال",
  "featured": false,
  "tags": ["وسم", "وسم"],
  "faq": [{"q": "سؤال؟", "a": "إجابة."}],
  "sources": [{"name": "المصدر", "url": "https://..."}]
}
```

3. **شغّل `python3 build.py`** — تُنشأ الصفحة تلقائياً، ويُضاف الرابط إلى:
   - `sitemap.xml` تلقائياً،
   - فهرس المقالات `/articles/`،
   - صفحة القسم `/categories/<category>/`،
   - قسم الأسئلة الشائعة `/faq/`،
   - `search-index.json` (للبحث السريع في الترويسة).

4. **اربط المقال**: أضف داخل `content/bodies/` روابط داخلية وصفية إلى المقال الجديد من المقالات ذات الصلة، وأضفه في قائمة «مقالات ذات صلة» إن كان في نفس القسم (تلقائي).

## 5. ما الذي تنفّذه الآلية تلقائياً؟

| المهمة | الأتمتة |
|---|---|
| `sitemap.xml` | يتولّد من المحتوى مع `lastmod` و`changefreq` و`priority` لكل رابط |
| `robots.txt` | ثابت، مع `Sitemap:` و`Host:` |
| `ads.txt` | ثابت، عدّل سطر publisher فيه مرة واحدة |
| العنوان والوصف والCanonical | من `meta/*.json` لكل صفحة |
| Open Graph و Twitter Card | تلقائي لكل صفحة + صورة `og-cover.png` |
| JSON-LD | `Organization` + `WebSite` (الرئيسية)، `BlogPosting` + `BreadcrumbList` + `FAQPage` (المقالات)، `ItemList` (الأقسام)، `BreadcrumbList` (الصفحات الثابتة) |
| فهرس البحث | `search-index.json` |
| إحصاءات القراءة | تُحسب من عدد الكلمات تلقائياً |
| روابط «مقالات ذات صلة» | تُختار من نفس القسم تلقائياً |

## 7. النشر

الموقع ملفات ثابتة بالكامل، ويكفيه أي استضافة: Netlify، Vercel، Cloudflare Pages، GitHub Pages، أو استضافة تقليدية Apache/Nginx.

**Netlify / Cloudflare Pages:**
1. اسحب مجلد `site/` إلى لوحة المشروع أو اربطه بمستودع مستودع Git مع وضع مجلد `site` كـ Publish directory.
2. اجعل أمر البناء `python3 build.py` ومجلد النشر `site` (إن أردت البناء من المصدر).

**استضافة تقليدية:** ارفع محتوى `site/` إلى `public_html/`.

**شرط أساسي:** كل الروابط الداخلية **مسارات مطلقة تبدأ بـ `/`**، لذا يجب أن يكون النطاق في الجذر (الجذر (root domain)) أو تبدّلها في `build/content/site_config.py` ثم أعد البناء.

## 11. نسخة Blogger (اختياري)

إن أردت تعديل الموقع من **لوحة Blogger** بدل الملفات، فالحزمة جاهزة في `blogger/`:

| الملف | الغرض |
|---|---|
| `theme.xml` | ثيم Blogger كامل بنفس التصميم: RTL، وضع ليلي، قائمة جوال، فهرس مقالات، شريط كوكيز، ومتغيرات ألوان قابلة للتغيير من مصمم Blogger |
| `import-posts.xml` | استيراد 16 مقالاً دفعة واحدة (مع الأسئلة الشائعة ومصادر بيطرية وFAQPage Schema) |
| `import-pages.xml` | استيراد 6 صفحات ثابتة (من نحن، اتصل بنا، الخصوصية، الشروط، الأسئلة الشائعة) |
| `build_blogger.py` | يولّد الملفات الثلاثة أعلاه من المحتوى الأصلي — يُشغَّل بعد أي تعديل |

**الفرق عن النسخة الثابتة:** لا تحتاج رفع ملفات عبر FTP، لكن Blogger يحدّد شكل روابط الصفحات (`/p/about.html`) ولا يسمح بتغيير الرابط بعد النشر، كما أن بعض مزايا SEO (FAQ Schema، ملف sitemap) يديرها Blogger بنفسه.

الخطوات الكاملة في [`docs/دليل-Blogger.md`](docs/دليل-Blogger.md).

## 12. معايير الجودة المطبّقة

- **RTL أصيل**: كل التخطيطات والحدود تعمل بـ `inset-inline` لا `left/right`.
- **Mobile-first**: نقاط التوقف عند 640 و900 و1100 بكسل، والقائمة تتحول إلى لوحة جانبية تحت 900 بكسل.
- **إمكانية الوصول**: رابط تخطٍّ، `aria-*` على العناصر التفاعلية، تباين ألوان مناسب، دعم `prefers-reduced-motion`، وحجم خط أساس 17px.
- **الأداء**: خطوط مستضافة ذاتياً (بدون طلب لطرف ثالث)، SVG بدل الصور النقطية، JavaScript واحد بحجم ~12KB، ولا مكتبات خارجية.
- **CLS منخفض**: مساحة كل وحدة إعلانية محجوزة مسبقاً بارتفاع ثابت.
- **لا نوافذ منبثقة مزعجة**: شريط موافقة واحد أسفل الشاشة، قابل للإغلاق، ولا يعترض القراءة.
